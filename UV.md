# uv Notes

uv is a fast Python package and project manager. It replaces `pip`, `venv`, `pip-tools`, `pyenv` and `pipx`.

## Key files

| File | What it is | Commit to git? |
|---|---|---|
| `pyproject.toml` | Your dependencies and project settings | Yes |
| `uv.lock` | Exact locked versions of every package (generated by uv, don't edit by hand) | Yes |
| `.python-version` | The Python version this project uses | Yes |
| `.venv/` | The virtual environment (can be rebuilt any time) | No |

## The usual workflow

1. `uv init` to create a new project
2. `uv add <packages>` whenever you need something, at the start or later
3. `uv run main.py` to run your code
4. Commit `pyproject.toml` and `uv.lock`
5. Anyone else runs `uv sync` to get the same environment

## Starting a project

```bash
uv init myproject          # create a new project in a new folder
uv init                    # turn the current folder into a uv project
uv init --lib mylib        # create a library or package instead of an app
```

## Python versions

```bash
uv python list             # show installed and available Python versions
uv python install 3.12     # install a Python version (no system install needed)
uv python pin 3.12         # set the project's version (writes .python-version)
```

## Managing dependencies

```bash
uv add requests              # add a package
uv add "requests>=2.31"      # add with a version constraint
uv add requests pandas       # add several at once
uv add --dev pytest ruff     # dev-only tools (testing, linting)
uv remove requests           # remove a package
uv tree                      # show the dependency tree (what depends on what)
```

## Upgrading packages

```bash
uv lock --upgrade                     # upgrade all packages to the latest allowed versions
uv lock --upgrade-package requests    # upgrade only one package
uv sync                               # install the updated versions into .venv
```

## Running things

```bash
uv run main.py                 # run your code; the environment is synced automatically
uv run pytest                  # run any tool installed in the project
uv run --with rich main.py     # run once with an extra package, without adding it
```

You don't need to activate the venv when you use `uv run`. If you prefer to activate it anyway:

```bash
source .venv/bin/activate      # activate (macOS/Linux)
deactivate                     # leave the venv
```

## Syncing the environment

```bash
uv sync             # make .venv match uv.lock exactly (use after cloning or pulling)
uv sync --locked    # in CI or on a server: fail if uv.lock is out of date
```

## Global CLI tools (not part of the project)

```bash
uvx ruff check .          # run a tool once without installing it
uv tool install ruff      # install a tool globally on your machine
uv tool list              # list globally installed tools
uv tool uninstall ruff    # remove a global tool
```

## Single-file scripts (no project needed)

```bash
uv add --script myscript.py requests    # stores dependencies inside the script itself
uv run myscript.py                      # uv installs them automatically when it runs
```

## requirements.txt

You don't need one in a uv project. `pyproject.toml` and `uv.lock` replace it.

```bash
uv add -r requirements.txt                               # import from an old project (migration only)
uv export --format requirements-txt > requirements.txt   # generate one if a tool or server requires it
```

Never write `requirements.txt` by hand in a uv project, because it goes out of date.

## Maintenance

```bash
uv self update     # update uv itself
uv cache clean     # clear uv's download cache if disk space is low
uv --version       # check the uv version
```

## Good practices

- Always use `uv add`, never `pip install`. `pip install` doesn't record the package in `pyproject.toml`.
- Commit `pyproject.toml`, `uv.lock` and `.python-version`.
- Don't commit `.venv/`.
- If `.venv` breaks, delete it and run `uv sync` to rebuild it.
- Never edit `uv.lock` by hand.
- Use `uv sync --locked` in CI or for deployments.

## pip to uv quick map

| Old way | uv way |
|---|---|
| `python -m venv .venv` | `uv venv` (or it happens automatically) |
| `pip install requests` | `uv add requests` |
| `pip uninstall requests` | `uv remove requests` |
| `pip install -r requirements.txt` | `uv sync` |
| `pip freeze > requirements.txt` | `uv export --format requirements-txt > requirements.txt` |
| `python main.py` | `uv run main.py` |
| `pipx run black` | `uvx black` |
| `pyenv install 3.12` | `uv python install 3.12` |
